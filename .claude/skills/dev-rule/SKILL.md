# 开发规范

## 触发条件
用户每次提出开发代码，迭代请求，修改代码等操作时

## 初始化方面
- 项目代码处于初代|未开发状态时，先明确用户要求，在docs/project/..中生成项目的定位与理念|依赖与API|架构设计|迭代路线图|快速开始|README。并在每次开发时，如有需添加|修改内容，在上述文件中同步
## 开发方面

- 每次迭代前，先在docs/plans/..中写好本次更新的plan.md，根据plan执行。plan要求包括 复杂度等级,要开发的模块，验收标准，技术债务
- 发现bug时，需到docs/bugs/..中报告当前版本的代码bug，包含严重等级| bug描述 | 具体定位 | 可能修复方案 |是否已修复
- 对于不确定的决策，生成决策到docs/actions/..中，等待用户编辑与修改。最终执行剩余决策。
- 出现较大更新时，总结项目status到docs/status/..中，文件名未[日期-V版本],尽可能精简的描述当前状态
- 不得擅自删除大批量文件|API，将其归结为不确定决策
- 补丁失败 N 次就重新审视架构，探索重构必要性
